# Offline DevKit v0.4.0 — gzip JSONL checks

直接检查 gzip 压缩日志，保留解压后的行号、严格 JSON 规则和有限错误样本。文件与二进制标准输入都显式使用 `--gzip`：

```bash
python offline-devkit.pyz jsonl records.jsonl.gz --gzip --json
```

压缩流截断、CRC、长度或压缩格式错误设置 `complete=false`、说明 `read_error` 并返回 2。已检查的计数会保留，但不能代表完整文件；即使 `invalid_lines=0`，也须检查退出码和完整状态。多个 gzip member 连续读取，单行上限按解压后字节计算。

下载 `offline-devkit.pyz` 和 `SHA256SUMS.txt`，按[校验说明](https://github.com/lashonbakker-crypto/offline-devkit/blob/main/docs/publishing.md)核对文件；Python 3.10+ 即可运行，无需 pip 或第三方运行依赖。工具在本机处理数据，不改写输入，不生成解压文件。它没有总解压量或运行时间预算，也不验证业务 schema。

源码包含真实子进程、便携包、损坏压缩流和连续 member 的回归测试。安装入口与公开下载附件使用同样的 gzip 例子验证；实际平台结论见发布后追加的[验证记录](https://github.com/lashonbakker-crypto/offline-devkit/blob/main/docs/publishing.md)。这不是性能或生产规模验证。

English: v0.4.0 adds explicit `jsonl --gzip` for compressed files and binary stdin. Record limits and physical line numbers apply after decompression. Invalid records or incomplete/corrupt compressed streams return 2; check `complete` as well as counters. Concatenated members remain one continuous stream. Processing is local and read-only, with no total decompression or runtime budget. Python 3.10+ is required. Verify the downloaded archive against its checksum; source and published-download checks are recorded separately in the validation notes.
