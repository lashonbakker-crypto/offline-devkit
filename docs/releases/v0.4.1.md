# Offline DevKit v0.4.1 — clearer input errors and easier first runs

这个补丁版本把已合并的路径与 JSONL 参数错误修复带到单文件包，并纳入 `sizes --top N` 的报告选择优化。继续支持 Python 3.10+、标准库零第三方运行依赖和只读本地处理。

## 修复与改进

- `json`、`jsonl`、`dupes`、`sizes` 遇到无法展开的 `~` / `~用户名` 路径时，给出可读输入错误并返回 2，不再泄漏 `RuntimeError` traceback。只在路径展开边界转换异常，目录链接与 Windows 重解析点策略不变。
- JSONL 的 `--max-line-bytes` 范围为 `1..sys.maxsize - 3`；过大的正整数会在读取记录前返回范围错误和退出码 2。普通文件、标准输入及 gzip 共用规则，默认仍为 1 MiB。
- `sizes --top N` 采用标准库堆选择，减少小 N 时报告构造中的临时排序分配；顺序和完整报告字段保持不变。完整扫描仍保存 O(n) 文件元数据，大 N 不保证更快。附带基准只测已经收集元数据后的报告构造，不代表磁盘扫描或整个进程的内存。
- 源码新增首次体验、Python 默认 JSON 设置对比与消费者 GitHub Actions 两文件配方。配方在输入路径解析或归档家目录展开失败时返回 2，并在工具准备前停止；更新时需要替换复制到自己仓库的 helper。默认下载固定附件需要网络；`--archive` 可使用匹配的已有附件并强制核对哈希，数据检查仍在本地运行。

## 下载与复现

从同一 Release 下载 `offline-devkit.pyz` 和 `SHA256SUMS.txt`，按[校验说明](https://github.com/lashonbakker-crypto/offline-devkit/blob/main/docs/publishing.md)先核对 SHA-256。便携包包含 CLI、Python 源码与 MIT 许可证，需要 Python 3.10+；示例数据、演练脚本和 CI 配方在源码 ZIP / tar.gz 中，不包含在 pyz 内。

校验后，在下载目录运行：

```bash
python offline-devkit.pyz --version
python offline-devkit.pyz jsonl --max-line-bytes 999999999999999999999999999999 --json
```

第一条应输出 `offline-devkit 0.4.1` 并返回 0。第二条应立即报告允许的行上限范围、返回 2，无 JSON 报告和 traceback，不需要输入数据。

下载同版本源码并进入解压目录，可运行：

```bash
python scripts/try_jsonl.py
python scripts/compare_json_checks.py
```

首次体验应核对完整 gzip、重复键与截断 gzip 的检查器状态 `0 / 2 / 2`，最后显示 `Demo passed`。对比应显示默认解析接受重复键 / NaN、默认重新序列化改变示例数字写法，而 CLI 采用项目严格规则并保留格式化数字原文；最后显示 `Comparison passed`。演练自身返回 0 表示预期结果得到验证，包括坏样本被拒绝，不表示坏样本有效。Python 标准库也可通过回调配置这些规则；对比只针对默认设置。

本版本保留 gzip 完整性、严格 JSON、精确数字原文和只读报告规则。语法检查不验证业务 schema；gzip 没有总解压量或执行时间预算，目录扫描也不是文件系统快照。源码检查、发布构建和实际下载验证是三类独立证据；对应运行结果见 [Actions](https://github.com/lashonbakker-crypto/offline-devkit/actions) 与[验证记录](https://github.com/lashonbakker-crypto/offline-devkit/blob/main/docs/publishing.md)，不要仅凭本说明判断发布已成功。

## English

v0.4.1 brings the merged input-error fixes into the portable archive and includes the `sizes --top N` report-selection optimization. Python 3.10+, standard-library-only runtime dependencies and read-only local processing remain the requirements.

- All four commands turn unresolved home paths into readable input errors with exit 2 rather than a RuntimeError traceback. Only the home-expansion boundary is changed; directory symlink and Windows reparse-point handling is preserved.
- JSONL line limits must be within `1..sys.maxsize - 3`. Oversized positive values are rejected before reading records, including file/stdin and plain/gzip input. The default remains 1 MiB.
- Heap selection reduces temporary report-construction allocations when N is small, preserving order and report fields. Full scans still retain O(n) metadata, large N is not guaranteed faster, and the synthetic benchmark does not measure disk scanning or whole-process memory.
- The source distribution includes a disposable first-run demo, a comparison with Python's default JSON settings, and a two-file consumer GitHub Actions recipe. The recipe also handles unresolved home paths and input-path resolution errors before tool preparation. Existing consumers must update their copied helper separately. Default preparation downloads a fixed archive; `--archive` uses matching existing bytes without network and still verifies the checksum. Data checks remain local.

Download both release assets and verify SHA-256 before executing the archive. `python offline-devkit.pyz --version` should print `offline-devkit 0.4.1` and exit 0. The oversized line-limit command above should immediately print a range error and exit 2, without a JSON report, traceback or data input. The pyz contains the CLI, source modules and license; sample data, demos and CI files are in the source ZIP / tar.gz.

From the extracted matching source, the two demo commands above should end with `Demo passed` and `Comparison passed`. Their own exit 0 means the expected outcomes were verified, including bad samples rejected with validator exit 2. Python can implement strict policies through hooks; the comparison covers only its defaults. These checks do not validate application schemas, establish filesystem snapshots, or impose a total gzip decompression/time budget. Source CI, publishing and actual downloaded-asset checks remain separate evidence; consult the linked runs and verification notes for their actual results.
